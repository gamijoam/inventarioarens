Auditoría y Desarrollo — Módulo de Movimientos Manuales de Inventario
1. Objetivo del proyecto

Actualmente el sistema manejaba los movimientos de inventario principalmente mediante dos procesos:

Ingresos: mediante compras.
Salidas: mediante traslados entre almacenes.

Esta estructura funcionaba para operaciones normales, pero dejaba un vacío para situaciones reales de operación, por ejemplo:

Un jefe necesita retirar un producto para uso interno.
Se pierde o daña un producto.
Se requiere realizar un ajuste manual.
Se encuentra mercancía que debe reincorporarse.
Se necesita registrar consumos internos.

En un sistema ERP profesional es necesario contar con un módulo independiente de Movimientos Manuales de Inventario, manteniendo:

Arquitectura actual del sistema.
Sistema de permisos existente.
Multiempresa / tenancy.
Auditoría completa.
Trazabilidad de cada modificación de stock.

 ↓
Aprobación
 ↓

3. Propuesta implementada

Se creó un nuevo flujo:

Movimientos Manuales

Nuevo concepto:

Solicitud de movimiento
          |
          ↓
      Pendiente
          |
     ┌────┴────┐
     ↓         ↓
 Aprobado   Rechazado
     |
     ↓
 Movimiento real de stock

La regla principal:

Crear una solicitud NO modifica stock.
El stock solamente cambia cuando un usuario autorizado aprueba el movimiento.

Fase 3 — Integración con inventario

Se integró con el servicio existente de movimientos.

Objetivo:

No crear una segunda lógica de inventario.

La arquitectura quedó:

Movimiento Manual
        |
        ↓
Servicio Inventario existente
        |
        ↓
Stock
        |
        ↓
Kardex

Esto evita:

Diferencias de stock.
Movimientos duplicados.
Kardex inconsistente.

5. Pruebas realizadas

Se crearon pruebas automatizadas para validar:

Workflow

Validaciones:

✅ Crear movimiento pendiente.
✅ No modificar stock al crear.
✅ Aprobar genera movimiento inventario.
✅ Rechazar no genera movimiento.

Permisos

Validaciones:

✅ Usuarios autorizados pueden aprobar.
✅ Usuarios sin permisos no pueden aprobar/rechazar.

Auditoría

Validaciones:

✅ Guarda aprobador.
✅ Guarda fecha aprobación.
✅ Guarda rechazador.
✅ Guarda motivo rechazo.
